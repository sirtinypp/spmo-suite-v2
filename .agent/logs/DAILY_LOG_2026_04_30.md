### Root Cause Analysis
1. **Primary:** Local `settings.py` used `DJANGO_SECRET_KEY` but PROD's `docker-compose.yml` passes `DJANGO_SECRET_KEY_GAMIT`. Direct file copy broke the secret key chain.
2. **Secondary:** Manual insertion of a `socialaccount_socialapp` DB record conflicted with allauth's `settings.py`-based APP configuration. The newer allauth version reads credentials from `settings.py` directly — having a duplicate in the database caused an internal crash.
3. **Tertiary:** `ALLOWED_HOSTS` in local settings defaulted to `localhost` only, rejecting the `gamit-sspmo.up.edu.ph` domain.

### Lessons Learned
- **NEVER** manually copy `settings.py` to servers. Environment-specific config must come from `.env` files and `docker-compose.yml`.
- **NEVER** insert allauth DB records when `SOCIALACCOUNT_PROVIDERS.APP` is configured in `settings.py`. They conflict.
- **ALWAYS** compare a working environment (DEV) against a broken one (PROD) before patching. Delta analysis > guesswork.
